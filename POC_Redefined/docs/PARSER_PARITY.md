# Parser Parity — JS (live) ↔ Python (offline)

Two parsers turn Verint `calendar-filter` data into the **same `CommandCard` contract**, for two runtimes:

- **`verint_extension/parse.js`** — JavaScript, runs in the extension in the RTA's browser. **The LIVE path.** Tested
  by `verint_extension/parse.test.js`.
- **`verint_calendar_parse.py`** — Python, the offline pipeline (`scenario_from_capture.py`, `verint_pipeline.py`).
  Produces fixtures / scenarios / demos.

They must stay in sync on the card contract. **As of 2026-06-11 they have diverged on derived agent metrics** — this
doc is the ledger + the path back to one source of truth.

## Parity matrix

| Capability | `parse.js` (live) | `verint_calendar_parse.py` (offline) | in sync? |
|------------|:---:|:---:|:---:|
| `adherence.violations` → CommandCards | ✅ | ✅ | ✅ |
| Card contract shape (id, lane, severity, agent, draftMessage, audit…) | ✅ | ✅ | ✅ |
| Field-merge census + targeted shapes per employee | ✅ (signal-based union) | ❌ (keeps one richest record) | ❌ |
| `adherenceInPercent` / `OutPercent` (from `adherenceSummary`) | ✅ | ❌ (hardcoded 0) | ❌ |
| `shiftStartIso` / `shiftEndIso` / `shiftSpanMinutes` | ✅ | ❌ | ❌ |
| `productivePaidMinutes` / `productiveWorkMinutes` | ✅ | ❌ | ❌ |
| Flag normalisation (string booleans) + Date-value time compare | ✅ | n/a (not yet ported) | — |

**Consequence:** live cards carry richer agent metrics than offline/scenario cards. `scenarios_epic.ts` shows
`adherenceInPercent: 0` because it was generated by the Python path. Demos built offline **understate** what the live
extension now shows.

## Conformance today

- **JS:** `parse.test.js` golden tests lock the derivations + the card contract + the field-merge + filters.
- **Python:** rules-core tests exist (`test_verint_triage`, `test_verint_normalize`, `test_verint_pipeline`,
  `test_card_builder_live`) but **none cover the new derivations** (they don't exist in Python yet).

## Path to one source of truth (recommended order)

1. **Now —** this doc is the contract + divergence ledger; **`parse.js` is canonical** for the derivations.
2. **When the Python path is next needed for live-parity demos —** port `deriveAdherence` + `deriveShiftProductive`
   + the field-merge into `verint_calendar_parse.py`, and add a **golden-fixture conformance test**: run the SAME
   synthetic capture through both parsers and assert identical cards.
3. **Production —** collapse to one implementation behind a versioned `CommandCard` contract (schema once + a single
   parser, or generate one language from the other). This is the "versioned contract + golden-fixture conformance
   test" from the productionization plan.

## Keep-in-sync checklist (when touching either parser)

- [ ] Card contract fields unchanged, or changed in **both** parsers.
- [ ] Derivation formulas match (adherence %, shift open/close, productive minutes).
- [ ] Re-run `node --test verint_extension/parse.test.js` **and** the Python `tests/`.
- [ ] Update the parity matrix above.
