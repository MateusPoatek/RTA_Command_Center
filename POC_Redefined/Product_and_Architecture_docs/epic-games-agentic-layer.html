Epic Games Agentic Layer

A proposal for a small set of AI agents on top of the Epic Games RTA solution, built on Google's agent platform, and a clear list of where AI is not used.

Summary

The RTA solution captures workforce data, joins it, applies alert rules and computes KPIs. Almost all of that is deterministic on purpose. We propose six advisory agents on top, where the input is language or where the work is investigation. They are delivered to employees through Gemini Enterprise and built with Google's agent tooling. This page is as clear about where we do not use AI as about where we do.

  • The deterministic core stays deterministic: capture, join, alert rules, KPI math, dispatch and report numbers.
  • Gemini Enterprise is the employee-facing front door for a few advisory, read-only agents, grounded on data the core already produces.
  • Nothing an agent says changes a KPI, an alert, a dispatch or a schedule. Agents hold no write credentials (AC-001).
  • Every agent has a named human checkpoint and a success metric we can measure. We start with the two lowest-risk agents.
Confirm with Google. Product names, editions, features and limits in this page reflect public information as of writing (2026). They are our understanding, not a commitment. Section 8 lists what we ask Google to confirm.

1. The rubric: when AI, when not

We use one rule set for every capability. A capability must pass the left column and hit none of the right column to get an agent.

Use an agent when…Never use an agent when…
The input is unstructured language (questions, SOP text, free-text reasons, discovery notes).The output is a number someone is paid, billed or scored on.
The output is advisory: an answer, a draft, a suggestion.The result is a rule that must be explainable and auditable. The same input must always give the same output.
A human reviews the output before anything happens.The step acts on an external system: sends, posts, writes, schedules or changes a setting.
An error is cheap and visible, and the answer can cite its source rows.A wrong answer would be hard to notice or expensive to undo.

2. What stays deterministic, and why

These parts produce numbers and decisions that people act on. They must be exact, reproducible and explainable. Each row links to the lesson in the engineering guide (POC_Redefined/Product_and_Architecture_docs/rta-board-engineering-guide.html#lessons) that shows why. The lessons were found by hand. That is the reason to keep the core as code and test it.

PartWhy it stays deterministicGuide lesson
Capture (Verint, GTT)Capture reads structured responses. The hard problems were scope and timing, not language. Reading a screen with vision is outside the governance envelope (AC-006). A model cannot fix a capture window it cannot see.3 (capture window), 6 (whole-floor capture)
GTT and Verint joinAn exact key first, then a loose match that must be unique and share at least 2 words. It matched 87 of 87 clock-ins. A model that guesses could silently put the wrong person on a wrong alert. The Workday ID will replace the loose match.7 (name join)
Alert rules A1–A6, severities, escalation timingA TL must be able to ask "why did I get this?" and get a rule and a threshold. Escalation at 5 and 15 minutes is a policy, not a prediction. False alerts erode trust, so every suppression case must be explicit and testable.8 (time off and no-shows), 1 (unpublished schedules), 5 (posting lag)
KPI and shrinkage formulasEvery KPI is a ratio of sums, measured as of the capture time. These feed the scorecard and headcount. The posting-lag and capture-window fixes moved shrinkage from 14.8% to 9.3% and from 49% to 9.8%. Math like that must be exact and reproducible, so a model never computes or rounds it.2 (unpaid lunch), 3, 4 (wall-clock creep), 5
Dispatch and routingSending a message to a person is an action on an external system. Delivery follows fixed rules: Sev 1 to the TL, Sev 2 in a digest, once per escalation level, retry on server errors. No agent holds a send credential (AC-001).8 (false alerts), plus the delivery rules in guide section 5
Report numbersThe report is a record that WFM and the client read. Numbers come from the reconciler and are written once. An agent may write the words around them (agent 2), never the figures.4, 5 (numbers must hold still between captures)
The principle. Where the cost of a wrong answer is a wrong paycheque, a wrong alert or a wrong invoice, we use code and tests. Where the cost of a wrong answer is a re-read, we can use an agent.

3. Where agents make sense

Six candidates, in the order we would build them. All tools are read-only. Each agent is a custom agent built with the Agent Development Kit (ADK, Google's open-source framework for building agents) and run on Vertex AI Agent Engine (Google's managed runtime for agents). Employees reach them through Gemini Enterprise (Google's enterprise AI platform and the successor to Google Agentspace).

1. Floor Q&A for RTAs, WFM and Ops

Problem
Answers to "what happened on the floor?" need a person to dig through the Details screen and reports.
Agent
A Gemini Enterprise agent that answers questions about KPI history and reports. Example: "why did Payments shrinkage rise after 14:00?"
Tools (read-only)
Read-only BigQuery views through a BigQuery data agent or MCP Toolbox for Databases (an open-source MCP server for databases). Report files in Cloud Storage.
Human checkpoint
The asker. Every answer shows the rows it used.
Guardrails
Tokenised names and IDs. Numbers are quoted from rows, never calculated by the model. "I do not have data for that" is an accepted answer. Model Armor screens prompts and responses.
Success metric (to measure)
Share of answers with row citations. Share of golden questions answered correctly. Share of answers where a reviewer finds an uncited number.

2. Shift-report narrative

Problem
The report has the numbers. Reading them into a summary for the client takes WFM time every shift.
Agent
Writes prose only, around deterministic numbers in the report JSON. A number validator rejects any figure not present in the source.
Tools (read-only)
The report JSON for one account and day. Prior-day report for comparison.
Human checkpoint
WFM reads and approves the narrative before the report is released.
Guardrails
Validator runs outside the model. A draft that fails is not shown; the report ships with the standard rule-based text. Names are tokenised.
Success metric (to measure)
Share of drafts that pass the validator first time. Share of drafts WFM accepts without edits. Minutes of WFM time per report.

3. Data-quality investigator

Problem
When a number looks wrong, an engineer repeats the checks we did by hand for the eight lessons.
Agent
Triggered when an invariant breaks: a shrinkage jump between captures, a join-rate drop, a foreign organization in the capture, a roster versus GTT gap. It runs read-only diagnostics and drafts a ticket.
Tools (read-only)
Diagnostic queries over BigQuery views: capture census, join log, funnel counts, posting-lag distribution. No access to raw payloads.
Human checkpoint
An engineer reads the draft ticket and files, edits or discards it.
Guardrails
It drafts only. It does not fix data, change a threshold or restart anything. The ticket must list the queries it ran.
Success metric (to measure)
Share of past incidents it identifies the right cause for, on the golden set. Share of tickets engineers keep. Time from trigger to a usable draft.

4. Account-onboarding assistant

Problem
Each new account needs a tenant manifest: Verint organization pattern, GTT functional area and sites, clock system, time zone. Engineer time per account drives the cost model (4 accounts per engineer).
Agent
Reads discovery notes and sample captures and drafts the manifest, with a note on every field it is unsure about.
Tools (read-only)
Discovery documents, the manifest schema, the census of Verint organization names for the account.
Human checkpoint
An engineer reviews and approves. The manifest goes through the normal pull request and deploy path (AC-003).
Guardrails
Output must validate against the manifest schema. The agent has no access to the deploy pipeline. Regex patterns are tested on the census before approval.
Success metric (to measure)
Fields accepted without change. Engineer minutes per onboarding versus today.

5. SOP and rules Q&A for Team Leads

Problem
TLs ask "what do I do for this alert?" or "why am I seeing this?" and the answer is in documents they do not open.
Agent
Gemini Enterprise search over the ANA SOP, the alert rules and the engineering guide. Answers with quotes and links.
Tools (read-only)
Document index only. No operational data.
Human checkpoint
The TL can open the source passage. The SOP stays the authority.
Guardrails
It explains rules; it never overrides them or changes a severity. It answers only from the indexed documents.
Success metric (to measure)
Share of answers with a document citation. Share of golden questions answered correctly. TL feedback on usefulness.

6. "Other" reason normaliser

Problem
When a TL presses "On it" and picks "Other", the reason is lost to analysis. The board offers only fixed reasons today; this agent needs a free-text box after "Other" (a small board change, planned with it).
Agent
Maps free-text reasons to the SOP categories as a suggestion.
Tools (read-only)
The list of free-text reasons and the SOP category list.
Human checkpoint
WFM accepts or rejects each suggestion in a review list.
Guardrails
A reason explains an alert. It never reclassifies it for the scorecard, and neither does this agent. The suggestion is stored beside the original text, never over it.
Success metric (to measure)
Share of suggestions WFM accepts. Share of "other" reasons that fit an existing category.

Deferred on purpose

IdeaWhy we wait
An LLM suggests matches for the unresolved join residueThe deterministic join already matched 87 of 87 in the reviewed capture, and the Workday ID is the planned key. If a residue remains, a model could suggest candidates and a human would confirm each one. Revisit after Workday.
Proactive or predictive alertingIt moves an agent from advising to acting on people. We have no baseline for accuracy and it touches the alert rules. Revisit only after phases 1 to 3 give us measured trust.

4. Reference architecture

Agents sit beside the core, not inside it. The only connection is a one-way read through tokenised, read-only views. Model Armor (Google's service that screens prompts and responses for injection and sensitive data) sits in front of the agents. Everything runs inside a VPC Service Controls perimeter (VPC-SC, Google's data-exfiltration boundary).

flowchart LR
  U["Employees: RTA, WFM, Ops, TL"] --> GE["Gemini Enterprise (front door)"]
  subgraph PERIM["VPC-SC perimeter"]
    GE --> MA["Model Armor (screen prompts and responses)"]
    MA --> AG["Custom agents (ADK on Vertex AI Agent Engine)"]
    AG --> MCP["MCP tools (read-only)"]
    MCP --> BQ["BigQuery views (tokenised, read-only)"]
    MCP --> GCS["Cloud Storage reports (read-only)"]
    AG --> LOG["Audit log: prompts, responses, tool calls"]
    subgraph CORE["Deterministic core: no agent code, no agent access"]
      CAP["Capture"] --> JOIN["Join"]
      JOIN --> RULES["Alert rules and KPIs"]
      RULES --> DISP["Dispatch"]
    end
    RULES -->|"writes views"| BQ
    RULES -->|"writes reports"| GCS
  end

Read the diagram this way.

  • The core writes the views and the reports. The agents' tools can only read them.
  • There is no arrow from any agent to capture, alert rules, KPIs or dispatch. That missing arrow is the design: agents cannot reach the core.
  • The LLM sits behind a backend proxy and is a swappable seam (AC-004). Gemini is the first choice here. The seam stays in place so another model can be used if needed.
  • Names and IDs are tokenised before data reaches any view the agents read. De-tokenisation happens only at the user interface, for users who may see names.

5. Guardrails

GuardrailWhat it means
No write credentialsThe agents' service identity has read-only IAM on views and report files. It has no send, publish, write or deploy role (AC-001). No AI write path exists.
Tokenisation at the edgeNames and employee IDs are replaced by tokens before any LLM call. De-tokenisation happens only in the user interface, for permitted users. Raw capture payloads are already dropped after normalisation.
Swappable model seamThe LLM endpoint is backend-proxied and swappable (AC-004). The key never reaches a browser.
Model ArmorPrompts and responses are screened for injection and sensitive data before and after the model.
Audit trailPrompts, responses and tool calls are logged to the write-once audit store, with the same 90-day-plus retention as other audit data.
Eval harnessGolden questions from real incidents run in BigQuery on every agent or prompt change. A drop in score blocks release.
Cost capsA budget and a per-agent request limit, with an alert on both. Values are set after phase 1 measurement.
Human checkpointEach agent has a named checkpoint (section 3). An agent output never takes effect on its own.
Network and tenancyDefault-deny egress with an allow-list. Agents read only the tenant they are asked about. No cross-client data mixing (AC-003).
FallbackIf an agent is down or rejected, the board, alerts and reports work exactly as before.
